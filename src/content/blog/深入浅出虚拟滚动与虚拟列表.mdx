一万行记录摊在页面上，屏幕里同时露出来的往往只有十几行。剩下的那些，人还没滚到，浏览器已经为它们建好了节点、算过了布局。虚拟化要改的就是这件事：内容可以很长，文档里真正带着的节点，只覆盖视口附近的那一截。滚动条仍然按完整内容来走。

这件事拆成两层，缺一层另一层就算不下去。滚动层看滚动位置，决定这一帧要准备哪些索引，并维护整份内容的占位。列表层拿到这些索引，把对应的数据画进有限的节点，再把每条数据的高度交回去。滚动层没有这张高度表，不等高时就划不出窗口；列表层没有窗口，就不知道该准备几个节点。所以下面先把滚动层的几何关系定下来，再写列表层怎么认数据、怎么复用节点，最后用一帧里的输入输出把两边接上。

## 技术点

- 滚动层：可视区域、占位高度、窗口平移
- 列表层：数据快照、标识、节点复用池、可变高度
- 两层交接的输入和输出

## 前置知识

后文里这几个词不再混用。

- **索引**是条目在当前这份数据里的位置，从 0 计。滚动层用索引描述窗口。插入、删除、排序都会改写索引。
- **标识**是一条数据在列表生命周期里的身份。窗口滑动不会改变它。头部插入或重新排序之后，同一条数据仍应给出同一个标识。
- **宿主**是留在文档里的节点，或包住一条条目的组件实例。数据不是节点。复用池里存放的是宿主。
- **窗口**是一段索引区间，从 `start` 起，到 `end` 止，包含 `start`，不包含 `end`。它还可以比肉眼看见的区域略宽。

一个限了高度、又设了 `overflow: auto` 的元素，是滚动容器。滚动层直接用到三个量：

- `clientHeight`：视口高度，容器里边看得到的那一段。
- `scrollTop`：内容已经往上卷走多少。视口上沿在内容坐标里的位置，就是这个值。
- `scrollHeight`：内容总高度。滚动条的行程，来自它和视口高度的差。

视口盖住的是内容坐标上的区间 `[scrollTop, scrollTop + clientHeight)`。滚动，就是把这段区间在内容上滑动。`scrollTop` 的上限是总高度减去视口高度，浏览器会把超出的值钳住。

浏览器为一行建立元素之后，这一行就进入盒子树。默认情况下，视口以外的盒子也参与布局。节点一多，样式计算、布局、内存里的 DOM 对象都跟着涨。屏幕高 600 像素、行高 40 像素时，视口里大约 15 行。一万行里，这一帧用得上的就是这 15 行，再加上紧挨着视口的几行。

## 滚动层

滚动层只做几何。它不决定「第 25 条是哪一笔订单」，也不决定节点上的文本怎么写。它回答的是：给定总条数和每一条的高度，这一帧的窗口是哪一段索引，这段窗口的起点离内容顶部有多远，滚动偏移要不要为了保住眼前的内容而改一改。

### 可视区域

先假定每一行一样高，记为 `itemHeight`。不等高是在这个模型上改，不另起一套滚动。

给定 `scrollTop`、视口高度和条数，视口上沿、下沿各落在第几条，用除法就够了：

```js
function visibleRange(scrollTop, viewportHeight, count, itemHeight) {
  const start = Math.max(0, Math.floor(scrollTop / itemHeight));
  const end = Math.min(count, Math.ceil((scrollTop + viewportHeight) / itemHeight));
  return { start, end };
}
```

`scrollTop = 1000`、`itemHeight = 40`、视口 600、一共一万条：

- 上沿：`floor(1000 / 40) = 25`。第 25 条的顶在 1000，贴着视口上沿。
- 下沿：`ceil(1600 / 40) = 40`。可见区间是 `[25, 40)`，共 15 条。第 39 条占据 `[1560, 1600)`，下沿对齐视口下沿。第 40 条的顶正好在 1600，右开区间不包含它。

第 `i` 条在内容坐标里的顶是 `i * itemHeight`。宿主若用绝对定位、相对内容原点来摆：

```js
host.style.transform = `translateY(${index * itemHeight}px)`;
```

滚动过程中改的是偏移。`transform` 避免的是「为了挪一行，把周围的布局再算一遍」。文字本身那一次布局省不掉。

可以把它想成一条长卷上的一扇窗。卷有一万行那么长，窗里只夹着当前这十几行。`scrollTop` 是窗的上沿贴在卷的哪里。

```
内容坐标
0        1000      1600                         400000
|--------[ 视口 600px ]-------------------------|
          可见 [25, 40)
```

窗口常常比这块可见区域再宽一截，叫做过扫描。快滚时，合成器会先把已经画好的层移开，脚本下一帧才把新索引摆上。两侧预先留着几条，新露出来的缝上就有内容。固定行高时，在可见区间两侧各扩 `overscan` 条，再钳进 `[0, count)`：

```js
function windowRange(scrollTop, viewportHeight, count, itemHeight, overscan) {
  const start = Math.max(0, Math.floor(scrollTop / itemHeight) - overscan);
  const end = Math.min(
    count,
    Math.ceil((scrollTop + viewportHeight) / itemHeight) + overscan,
  );
  return { start, end };
}
```

`overscan = 2` 时，可见区间 `[25, 40)` 扩成窗口 `[23, 42)`。多出来的四条按自己的偏移放在视口外，不另加进总高度。过扫描填的是帧和帧之间的一小段位移。一帧里 `scrollTop` 跳了 2000 像素，两行盖不住，这一帧仍要按新位置重算整个窗口。单元格轻、行高固定，上下各 3 到 8 条通常够用；单元格重，就收小，边缘再露白再加。行高差得很多时，按像素向外扩，比按条数稳。

列表层会把整个窗口都画上，包括视口外的那几条。所以「渲染函数被调用」不等于用户看见了。看见与否，仍用这段视口区间判断。

### 占位高度

只把 15 个宿主放进容器，`scrollHeight` 就大约是 15 行。滚动条短得只能抖一下，`scrollTop` 也到不了 1000，窗口算法没有机会碰到后面的索引。

占位元素把总高度交回去。它不表示任何一条的内容，只占尺寸。固定行高时，高度是 `count * itemHeight`。一万条、行高 40，占位是 400000 像素。滚动条的比例、拖动滚动条能到达的位置，都跟每一行都在文档里时一致。行高不等时，占位是全部高度之和，也就是前缀和的最后一项。那些高度来自列表层，滚动层负责把它们累成占位。

两种摆法，几何是同一件事。

**一块占位，宿主绝对定位。** 占位留在正常流里，把容器撑到总高度。每个宿主 `position: absolute`，再用 `translateY` 放到该条的顶。宿主离开正常流，不会把占位再撑高。

**上下两段占位，宿主留在正常流。** 上面一段等于窗口起点之前的高度，固定行高时是 `start * itemHeight`。中间按顺序放窗口里的宿主。下面一段是剩余高度。三块相加仍是总高度。滚动时改两段的高度，宿主跟着文档流落到新位置。

用同一组数对一下。一万条、行高 40、`scrollTop = 1000`、窗口先按可见区间 `[25, 40)` 来看：

- 一块占位：高度 400000。第 25 条 `translateY(1000)`，第 39 条 `translateY(1560)`。
- 上下两段：上段 `25 * 40 = 1000`，中间 15 行共 600，下段 `(10000 - 40) * 40 = 398400`。三者相加仍是 400000。中间第一行的顶被上段推到 1000。

绝对定位的包含块必须是内容的顶，不能是视口的顶。上下两段里的宿主不要再设绝对定位，否则上段不再推动它们，行会叠在一起。会让视口里正在看的内容突然跳动的，主要是窗口起点之上、当前没有宿主的那段高度。那段只能来自高度缓存，不能靠量一个还不存在的节点。

### 窗口平移

`scrollTop` 从 1000 变到 1040，行高 40，可见区间从 `[25, 40)` 变成 `[26, 41)`。第 25 条离开，第 40 条进入。拖动滚动条时，`scrollTop` 可以一帧跳过几百条。窗口按新的 `scrollTop` 整段重算，不是一条一条挪过去。

滚动层这一帧公布三样东西：新的 `start` 和 `end`，窗口起点在内容坐标里的偏移，以及视口打算钉住的那条数据。钉住谁用标识，不在滚动层里挑选；滚动层只负责在拿到标识对应的新索引之后，把 `scrollTop` 设到该条的顶，再加上视口上沿在该条内部的那段距离。

节点个数保持在窗口长度附近。离开窗口的索引这一帧不再需要宿主，新进入的索引需要一个。同一帧里的多次滚动合成一次计算，监听用 `passive: true`，浏览器可以先滚动已有的层。程序自己为了修正高度而写的 `scrollTop`，不要再当成用户在滚，否则测量和修正会互相叫醒。

哪个宿主继续画哪条数据，是列表层的事。滚动层不在这里规定池子怎么领、怎么还。

### 不等高时怎么找窗口

行高各不相同时，第 `i` 条的顶不再是 `i * itemHeight`。滚动层维护前缀和 `offsets`：`offsets[0] = 0`，`offsets[i]` 是第 `i` 条的顶，`offsets[count]` 是总高度，也就是占位高度。第 `i` 条占据 `[offsets[i], offsets[i + 1))`。表里的每一格高度，由列表层按标识提供，滚动层按当前索引去读。

窗口起点是满足 `offsets[i] <= scrollTop` 的最大 `i`：

```js
function findStart(offsets, scrollTop) {
  const last = offsets.length - 2;
  let lo = 0;
  let hi = last;
  while (lo < hi) {
    const mid = (lo + hi + 1) >> 1;
    if (offsets[mid] <= scrollTop) lo = mid;
    else hi = mid - 1;
  }
  return lo;
}
```

`offsets = [0, 40, 100, 130]` 时，一共三条。`scrollTop = 100` 得到 2，`scrollTop = 99` 得到 1，`scrollTop = 0` 得到 0。一项和视口相交，当且仅当它的顶在视口下沿之前，并且它的底在视口上沿之后。高度必须非负，前缀和才单调，二分才有效。还没量过的条先用估计高度，否则占位是短的，那些条根本滚不到，也永远量不到。

把视口对准第 `index` 条，就是 `scrollTop = offsets[index]`。窗口外没有节点，不能等那个节点出现了再叫它自己滚进视口。高度还是估计值时，这一下对准的是估计位置。该条进入窗口、列表层量出新高度之后，若用户没有在滚，再按新的顶设一次。

测量带来的高度差记为 `delta`。前缀和从这条的下一项起到末尾都加上 `delta`，占位一起变。要不要改 `scrollTop`，看修正前这条的底边在不在视口上沿之上：

```js
function applyDelta(offsets, index, delta) {
  for (let k = index + 1; k < offsets.length; k++) offsets[k] += delta;
}

const oldBottom = offsets[index] + heights[index];
const delta = measured - heights[index];
heights[index] = measured;
applyDelta(offsets, index, delta);
if (oldBottom <= scrollTop) viewport.scrollTop = scrollTop + delta;
```

底边已经在上沿之上，多出来的厚度都在视口外面，`scrollTop` 加上 `delta`，上沿才继续对着原来的内容。底边还在视口里面，多出来的像素长在可见区域，`scrollTop` 不动。跨在上沿上的那一条（顶在上沿之上、底在上沿之下）就属于后者，不能因为顶边在上面就把整个 `delta` 加进去。同一帧里好几条一起变化，用更新前的偏移判断，把该加的 `delta` 加总，再改一次 `scrollTop`。

四条都估成 40，`offsets = [0, 40, 80, 120, 160]`，视口高度 100，`scrollTop = 80`。起点是 2。第 2 条量得 70，修正前底边 120，大于 80，底边在视口里，`scrollTop` 不动，总高度变成 190。换第 0 条量得 60，修正前底边 40，整条都在上沿之上，`scrollTop` 变成 100，从第 1 条起每条的顶都加 20。`delta` 为负时同样判断，结果小于 0 要钳住。

浏览器自己的滚动锚定只看文档里已经有的节点。窗口外的条不在文档里，它们变高、被插到前面，锚定都看不见。修正做在 `scrollTop` 和占位上。

人没滚、视口上方的高度却变了，用的是同一条规则。头部插入一段总高为 `h` 的内容，已有各条的顶都增加 `h`。更新前记下上沿所在那条的标识，以及 `scrollTop` 减去该条的顶；列表层在新快照里把标识换回新索引之后，滚动层把 `scrollTop` 设成新的顶，再加上那段距离。只记索引的话，插入之后钉住的是另一条。

## 两层交接

每一帧按这个顺序走，两边都不把对方的账再算一遍。

1. 滚动层用上一帧已经提交的高度表、当前 `scrollTop` 和视口高度，算出窗口，并给出锚点标识在这一帧快照里的索引。
2. 列表层只在这个窗口里领宿主、写数据、测量，交出高度变化。
3. 滚动层按变化落在锚点的哪一侧，改前缀和、占位，以及必要的 `scrollTop`，然后进入下一帧。

列表层拿到的输入是：

1. 当前快照上的窗口，从 `start` 到 `end`
2. 窗口起点在内容坐标里的偏移
3. 锚点标识。在这一帧的快照里，它能换成索引

列表层交回的输出是：

1. 每个索引对应的标识
2. 该标识的高度，并标明这是估计值还是实测值
3. 高度相对上一帧的变化量，以及这条数据在锚点的哪一侧

```typescript
type Range = { start: number; end: number };

type SizeChange = {
  key: string;
  index: number;
  prev: number;
  next: number;
};
```

节点摆在哪个偏移上，由滚动层用这些高度去算。列表层不改 `scrollTop`。窗口内部可以按普通文档流向下排，某一条变高，窗口自己会被撑开；会把视口里正在看的内容顶走的，是窗口起点之上那段没有宿主的高度。那段的变化必须出现在交回的 `SizeChange` 里。

只改缓存、不交变化，上方一张图加载完成后，正在读的那一行会被顶下去。只改滚动偏移、不改缓存，下一帧求和又用旧高度，跳动会在后面的帧回来。

变化相对锚点的规则，按「锚在该条顶边」来记：

- 索引小于锚点：在锚点上方。滚动偏移加上两次高度的差，画面才不动
- 变化的就是锚点：顶边不动，条目向下长，滚动偏移不变
- 索引大于锚点：只让总占位变长，滚动偏移不变

用户若已经滚进一条很高的条目内部，锚点还包括顶边之下的一段距离。只有这段距离之上的变化才调整偏移。水平列表把高度换成宽度。网格要先约定索引按行还是按单元格，高度表和窗口用同一种约定。

## 列表层

列表层消费窗口，不生产窗口。它要保证的是：窗口里每个索引画的都是该索引上的那条数据，离开窗口的宿主不带走上一条的状态，变过的高度下一帧仍然认得出是谁。

### 数据源是一份快照

滚动层只会说「给我第 i 条」。数据源必须能按索引取值，并回答现在一共有多少条。在这份快照被整份替换之前，同一个索引每次取出的条目和标识相同。

```typescript
type Source<T> = {
  count: number;
  item: (index: number) => T;
  key: (index: number) => string;
};
```

过滤、排序、在头部插入，都是换一份快照，不是在旧数组上改 `count`。同一帧里前半段用旧数组、后半段用新数组，索引会指到另一条上。滚动层手里若还拿着按旧快照算好的窗口，列表层换快照时要让它按新的条数、新的标识和新的高度重新要一次窗口。锚点标识在新视图里已经不存在，就改钉到仍在的邻近条目，或回到起点，并把窗口收进新的条数之内。

常见来源有三种，列表认的契约相同。

**内存中的数组。** 按索引取值是常数时间。只能向后走的游标，要先变成可以按下标读取的结构。

**映射出来的视图。** 搜索、筛选、排序得到的是另一份数组。源数据里的第 10 条，在视图里可能变成第 0 条，也可能被去掉。勾选记在业务标识上，视图更换后仍能对上；记在视图索引上，下一次筛选会贴到别的条目。

**按页填满的索引空间。** 总条数已知时，还没加载的下标也占位置，放占位条目，高度用估计值。否则窗口会把后面的真实数据提前画出来。占位条目的标识在真实数据到达后必须沿用：一开始就用服务端 id，或约定页号加页内序号一直用到这条被删。标识一换，高度缓存失效，宿主也会把「加载完成」当成「换了一条数据」。

总条数暂时未知时，列表可以随着已加载条数变长，交得出当前这段的占位，交不出最终滚动条比例。窗口靠近已加载范围的边缘时再请求下一页，请求返回后替换快照。请求是填充策略，不是绘制。

### 索引是地址，标识是身份

在头部插入一条时，原来排在 0 的那条变成 1，标识不变。高度若按索引存储，整表错一位；按标识存储，仍然能找到。锚点若只记了索引，插入之后钉住的就是另一条。

标识要满足三条：在当前快照里唯一；同一条逻辑数据换了快照仍然不变；不掺进会变的渲染结果，比如把标题和当前高度拼在一起。用索引做标识，只在这份快照的前缀不会插入、删除、重排时成立。没有业务 id 时，在进入列表之前补上稳定 id，不要在渲染时现造一个随机数，也不要悄悄退回索引。

位置是布局算出来的偏移。不能靠「离顶部多少像素」找回一条数据，也不能靠标识直接推出它这一帧的偏移。高度缓存用标识做键，交给滚动层时再按当前快照换成索引。

### 把条目写进宿主

渲染函数拿到条目、快照索引、这个宿主上一帧的标识，把数据写进节点。索引可以用于 `aria-posinset` 这类和位置有关的信息，`aria-setsize` 用快照条数。索引不用来认人。

```typescript
type Paint<T> = (
  el: HTMLElement,
  item: T,
  index: number,
  previousKey: string | null,
) => void;
```

宿主可能是旧的。只在新建时赋值，复用之后屏幕上会留下上一条的文本、属性和监听。标识没变的宿主，只更新能从数据推导的字段。数据里没有的非受控值不要重写。每一帧执行用空草稿覆盖输入框，标识复用留住了节点，半截输入也会被写掉。

勾选、展开、已经决定保留的草稿，放在数据里，或放在以标识为键的表里。节点上只放这一帧的投影。还没提交、也不打算进数据的临时状态，只有在「标识不变、这段时间不复位、渲染也不覆盖」时才能留在节点上。条目一旦离开窗口，这种状态要么已经进了那张表，要么就该丢。

### 复用池

池是已经创建好的宿主。窗口有多长就准备多少，变长再补，变短先闲置，不按数据条数创建。一万条和两万条，窗口仍是二十来个宿主时，池的规模不变。立刻销毁闲置宿主，会在视口尺寸或行高来回变化时反复创建。

第一帧按估计高度准备的池，可能小于实测之后的窗口。实测更矮，同一视口装得下更多条，滚动层下一帧会给出更长的区间，列表层必须能补宿主。池比窗口小还继续领，会把同一个宿主画两次，或直接拿不到节点。吸顶行若在滑出窗口后还要留在视口里，它使用单独的节点，不进这只普通池，也不要被拿去画别的数据。

**按槽位复用。** 第 i 个宿主永远画 `start + i`。窗口向前移一格，每个可见槽位都换绑。适合纯展示：纯文本、从图标数据里读出的勾选。写在节点上的状态会串到新的索引。

```typescript
function renderBySlot<T>(
  items: readonly T[],
  start: number,
  slots: HTMLElement[],
  paint: (el: HTMLElement, item: T, index: number) => void,
) {
  for (let i = 0; i < slots.length; i++) {
    const index = start + i;
    const el = slots[i];
    if (index >= items.length) {
      el.hidden = true;
      continue;
    }
    el.hidden = false;
    paint(el, items[index], index);
  }
}
```

当前快照里不存在的索引不要沿用上一帧的画面。超出条数的槽位藏起来。

**按标识复用。** 宿主记住标识。标识还在新窗口里，就留在这个宿主上；离开的归还；新来的从空闲宿主里领。窗口只移动一格时，只会换绑离开的那一个宿主。焦点、播放中的媒体、没有写入数据的选区，才留得下来。

```typescript
type Host = { key: string | null; el: HTMLElement };

function takeHost(pool: Host[], key: string): Host {
  const matched = pool.find((host) => host.key === key);
  if (matched) return matched;
  const blank = pool.find((host) => host.key === null);
  if (!blank) throw new Error('池比窗口小');
  blank.key = key;
  return blank;
}
```

标识必须唯一。两个索引共用一个标识，会先后写进同一个节点，第二次领取应当拒绝。在组件框架里，若这一帧只把窗口内的条目交给协调器，并且每条都带稳定标识，协调器就在做按标识复用，不必再手写一套 DOM 池。两种做法消费的是同一个窗口。

宿主和一条数据解开时，在换绑之前复位：文本和只对那条数据有意义的属性、为那条数据注册的监听、非受控输入和选区、媒体进度、临时图片地址、写在节点上的尺寸。焦点若还在即将归还的宿主里，先移走，避免它掉到文档根上。正式高度在标识缓存里，不在节点上。可以留下的只有与具体条目无关的结构：宿主元素、子节点骨架、通用样式。骨架上的内容不能留。标识没变就复位，列表稍一滚动，不该丢的输入会被清掉。

### 可变高度交回滚动层

每条高度都相同时，滚动层用除法即可，列表层不必测量。高度随内容变化时，偏移是前面各条高度之和。还没进过窗口的条目只有估计值。估计值参加这一帧的窗口计算，不表示以后不用再量。

```typescript
type SizeRecord = {
  height: number;
  source: 'estimate' | 'measured';
};

function readHeight(record: SizeRecord | undefined, estimate: number): SizeRecord {
  return record ?? { height: estimate, source: 'estimate' };
}
```

测量读宿主的边框盒，键是标识。同一个宿主下一帧可能已经换了数据。尺寸只留在节点上，换绑之后量到的是新数据，旧数据的高度却丢了。条目滑出窗口，宿主可以归还，记录留下。滚动层在它再次进入之前，还要用这条高度算占位。

一帧之内先写完窗口里的内容，再集中读取高度，最后一次交出变化。读一条、改一条样式、再读下一条，布局会跟着窗口长度涨。`ResizeObserver` 可以在布局完成后送尺寸，回调里同样按标识写入，不要在回调里同步改样式再读布局。

图片尚未解码、手风琴尚未展开、容器宽度或字号变化，都要把该标识标回待测。标成实测后又永不失效，第一次的错误高度会一直参与它上方的占位。视口变宽时按标识标回待测即可，不必把池拆掉。

实测和缓存旧值不同，才交出一条 `SizeChange`。比较前先把锚点标识换成这一帧快照里的索引，再按上一节的三侧规则，由滚动层决定偏移加不加。高度从 48 量到 48，不交非零变化，但要把来源从估计改成实测。

下面用六条数据把交接走完。高度里标出估计或实测。

| 索引 | 标识 | 高度 | 来源 |
|------|------|------|------|
| 0 | a | 40 | 实测 |
| 1 | b | 80 | 实测 |
| 2 | c | 40 | 估计 |
| 3 | d | 120 | 实测 |
| 4 | e | 40 | 实测 |
| 5 | f | 40 | 估计 |

滚动层给出的窗口是索引 1 到 5，也就是 b、c、d、e。锚点是 d，锚在 d 的顶边。池里准备 4 个宿主。c 进入窗口后量到 72。c 的索引 2 小于锚点索引 3，列表层交出：标识 c，旧高度 40，新高度 72。滚动层把偏移加上 32，缓存里 c 改成 72、来源改成实测。d 的顶边才不会被顶走。b、d、e 的高度没有变化，不交非零差值。

下一帧滚动层把窗口改成索引 2 到 6。列表层不算「为什么变成这四个」，只处理宿主：b 归还并复位；c、d、e 的标识还在，宿主不动，也不复位；f 领走空出来的宿主。f 量出来仍是 40，不交非零变化，来源改成实测。池的长度还是 4。后面再追加一百条，只要窗口仍是 4 个索引，宿主就不增加。

若这一帧不是窗口平移，而是在索引 0 插入一条新数据，a 到 f 的索引全部加一，标识不变。c 的高度仍然记在 c 上。锚点仍是 d。滚动层用 d 去新快照里找它现在的索引，而不是继续钉着插入前的 3。新插入的那一段在 d 的上方，它的高度要进滚动偏移，眼前这条才会留在原地。

## 两层对不齐的时候

这些错法都长在交接上。只改一边，另一边下一帧还会把旧数读回来。

**用索引当标识，同时允许头部插入或排序。** 高度、勾选和输入会整表移动，或在重排后贴错行。失效有两种样子：节点被当成全新的，输入丢失；节点留下，状态贴到了新索引上。第二种更难注意到。

**高度按索引缓存，或只留在节点上。** 窗口一滑动，滑出的位置被写成新条目的高度，上方占位跟着错。键用标识。交给滚动层时再换成当前索引。

**换绑时不复位，或标识没变却覆盖了非受控字段。** 按槽位复用时尤其明显。节点留住了，值仍然每帧被空数据写回。

**把估计值当成最终值。** 条目从未测量，或图片解码后没有把标识标回待测。重叠、空隙、滚动条长度不对，都从这里来。

**上方变高，却不交变化量，或交了变化却用错锚点的一侧。** 缓存已是新高度，滚动偏移还是按旧高度留下的数，视口被顶走。锚点自己向下长、下方变高，都不该加进偏移。

**同一帧混用两份快照。** 滚动层按筛选前的索引要窗口，列表层已经换成筛选后的数组。应当整份替换，用锚点标识重新取窗口。

**池按数据条数创建，或把渲染当成曝光。** 文档里仍然有完整的一份节点。窗口里多准备的条目也会走渲染函数，统计「看见」要用视口。

另外，`content-visibility: auto` 能让浏览器跳过屏外内容的布局和绘制，元素仍在文档里，节点数跟着条数走。`contain-intrinsic-size` 可以给还没布局的内容一个占位尺寸。那是渲染跳过，不是窗口加复用池。分页决定数据一次来多少，不决定页内有多少宿主。它们可以跟这两层同时存在，替代不了窗口、占位、快照和标识。

## 总结

长列表是两层合在一起的。

- 滚动层用 `scrollTop` 和视口划出可见区间，用过扫描把窗口略为加宽，用占位把总高度交回滚动条。固定行高用除法，不等高用前缀和。窗口平移时公布新的区间和起点偏移，不负责挑宿主。
- 底边在视口上沿之上的高度变化，以及头部插入，都要进 `scrollTop`。窗口外没有节点可以替你滚动。过扫描只填帧间的缝。
- 列表层拿到窗口、起点偏移和锚点标识，交回每个索引的标识、带来源的高度、以及相对锚点的变化量。
- 快照按索引读取。标识跨快照不变。池的长度等于这一帧的窗口。槽位复用实现直接，标识复用能留下仍在窗口内的节点。复位发生在换绑之前，标识没变的宿主不复位。
- 高度缓存以标识为键，比宿主活得久。估计值先参加求和，实测差异再交回滚动层。只改其中一层，下一帧会把另一层的旧数读回来。
