## 技术点

- 虚拟列表
- 数据快照
- 节点复用池
- 标识（key）
- 可变高度

## 前置知识

对下面几个词有固定的用法，后文不再混用。

- 索引（Index）

  索引是条目在**当前这份数据**里的位置，从 0 计。滚动层用索引描述窗口。插入、删除、排序都会改写索引。

- 标识（Key）

  标识是一条数据在列表生命周期里的身份。窗口滑动不会改变它。头部插入或重新排序之后，同一条数据仍应给出同一个标识。

- 宿主节点（Host）

  宿主是留在文档里的节点，或包住一条条目的组件实例。数据不是节点。复用池里存放的是宿主。

- 窗口（Window）

  窗口是滚动层算完后交给列表的一段区间：从 `start` 起，到 `end` 止，包含 `start`，不包含 `end`。另外附上这段区间在内容坐标系里的起点偏移。区间可以比肉眼看见的区域略宽，多出来的条目用来准备即将进入视口的内容。区间本身怎么划定，不在本文展开。

## 列表层坐在滚动层上面

条目一多，若为每一条都创建节点，创建、布局和绘制的成本会落在屏幕之外。虚拟化把文档里的节点数压到「当前要准备的那一段」。

这件事分成两层。滚动层看滚动位置，决定这一帧要准备哪些索引，并维护整份内容的占位，让滚动条仍然像在一份很长的文档上。列表层拿到这些索引，把对应数据画进有限的宿主。

可视区域怎么划、占位总高怎么累、滚动过程中哪一帧回收宿主，是滚动机制要解决的问题。列表层把它们当作已经算完的输入。

两层之间只交换固定的几样东西。

列表层拿到：

1. 当前快照上的窗口，从 `start` 到 `end`
2. 窗口起点在内容坐标系中的偏移
3. 锚点。锚点是视口打算钉住的那条数据，用标识表示。在这一帧的快照里，它能换算成索引

列表层交回：

1. 每个索引对应的标识
2. 该标识的高度，并标明这是估计值还是实测值
3. 高度相对上一帧的变化量，以及这条数据在锚点的哪一侧

节点摆在哪个偏移上，由滚动层用这些高度去算。列表层把窗口里的宿主排在已经算好的起点之后。窗口内部可以按普通文档流向下排：某一条变高，窗口自己被撑开。会让视口里正在看的内容突然跳动的，是窗口起点之上、当前没有宿主的那段高度。那段高度只能来自缓存。

所以列表层一帧里的顺序是固定的：认数据，领宿主，写条目，测量，把高度变化交回去。

### 和另外两种做法分开

`content-visibility: auto` 允许浏览器跳过屏外内容的布局和绘制。元素还在文档里，数据变长时节点数仍然跟着条数走。`contain-intrinsic-size` 可以给还没布局的内容一个占位尺寸。那是浏览器的渲染跳过，不是按窗口领取宿主。

分页改变的是数据一次来多少。一页之内如果仍为每一行创建节点，长页一样贵。分页可以给虚拟列表当加载策略，绘制仍然只覆盖窗口。

## 数据源

### 列表认的是一份快照

滚动层只会说「给我第 i 条」。数据源必须能按索引取值，并回答现在一共有多少条。

```typescript
type Source<T> = {
  count: number;
  item: (index: number) => T;
  key: (index: number) => string;
};
```

在同一份快照被换掉之前，`item` 和 `key` 对同一个索引必须给出稳定结果。随机数、读取时刻、尚未返回的请求，不能直接充当标识。

过滤、排序、在头部插入，都是换一份快照，而不是在旧数据上改 `count`。滚动层手里可能还拿着按旧快照算好的窗口。列表层改用新快照时，要让滚动层按新的条数、新的标识和新的高度重新要一次窗口。同一帧里混用两份快照，索引会指到别的条目上。

### 索引是地址，标识是身份

索引回答「它现在排在第几」。标识回答「它是哪一条」。

在头部插入一条时，原来排在 0 的那条变成 1，标识不变。高度若按索引存储，整表错一位；按标识存储，仍然能找到。锚点若只记了索引，插入之后钉住的就是另一条。列表层应交出锚点的标识，滚动层在新快照里找回它的新索引。找回的过程属于滚动层，标识和索引的对应属于列表层。

### 三种常见来源

**内存中的数组。** 条数就是长度，按索引取值是常数时间。窗口模型依赖这种随机访问。只能向后走的游标，要先变成可以按下标读取的结构，才能当数据源。

**映射出来的视图。** 搜索、筛选、排序得到的是另一份数组。源数据里的第 10 条，在视图里可能变成第 0 条，也可能被去掉。勾选若记在业务标识上，视图更换后仍能对上；记在视图索引上，下一次筛选就会贴到别的条目。

**按页填满的索引空间。** 总条数已知时，还没加载的下标也占位置。该位置放占位条目，高度用估计值。占位条目同样要有稳定标识：服务端已经给出 id，就用这个 id；只有页结构时，用页号加页内序号，真实数据到达后继续沿用。标识一旦换成另一个，高度缓存和宿主都会把「加载完成」看成「换了一条数据」。

总条数暂时未知时，列表可以随着已加载条数变长。滚动条拇指的比例，以及「已经滚到末尾」这件事，此时没有最终长度，只能随条数增长改写快照。列表能画增长中的条数，但不能在总长度未知时交出一份最终占位。

窗口靠近已加载范围的边缘时再去请求下一页，请求返回后替换快照。请求是数据源的填充策略，不是绘制本身。

## 条目渲染

渲染函数把一条数据写进宿主。它至少要拿到：条目、条目在快照中的索引、这个宿主上一帧绑的标识。

```typescript
type Paint<T> = (
  el: HTMLElement,
  item: T,
  index: number,
  previousKey: string | null,
) => void;
```

索引用来写和位置有关的信息。`aria-posinset` 可以用「索引加 1」，`aria-setsize` 用快照条数。索引不用来认人。同一条数据滑出窗口再回来，索引可能因为中间插入而变了，身份只看标识。

宿主可能是旧的。渲染函数要覆盖上一条留下的文本、属性和监听。只在新建节点时赋值，复用之后屏幕上会留下上一条的内容。

标识没变的宿主，只更新能从数据推导的部分。数据里没有的字段不要重写。每一帧都用空的数据值覆盖输入框，即使用标识复用留住了节点，半截输入也会被写掉。

挂上节点不等于用户看见了。窗口常常比视口略宽，多准备的条目已经执行过渲染。曝光、自动播放，要看条目是否进入视口。视口由滚动层判定。渲染函数这里只要避免把「函数被调用」当成「用户看见了」。

跟条目走的状态放进数据，或放进以标识为键的表。勾选、展开、已经决定保留的草稿，都属于这种状态。放在节点的非受控字段上，宿主换绑时会跟到下一条。

## 节点复用池

### 池里存放宿主

池是一组已经创建好的宿主。这一帧窗口有多长，池就准备多少；窗口变长时再补，变短时把多余宿主闲置。闲置优于立刻销毁。窗口长度会随视口尺寸和条目高度变化，反复创建会把省下的成本还回去。

池的容量跟着窗口走，不跟着数据条数走。一万条数据、窗口长度为 20，池里就是大约 20 个宿主。数据再增加一倍，池的规模不变。

滚动层决定这一帧窗口变了没有。列表层规定宿主换绑时要做什么。

### 按槽位复用

第 i 个宿主永远对应窗口起点之后的第 i 条。窗口向前移一格，每个槽位都换数据。

```typescript
function renderBySlot<T>(
  items: readonly T[],
  start: number,
  slots: HTMLElement[],
  paint: (el: HTMLElement, item: T, index: number) => void,
) {
  for (let i = 0; i < slots.length; i++) {
    const index = start + i;
    const item = items[index];
    const el = slots[i];
    if (!item) {
      el.hidden = true;
      continue;
    }
    el.hidden = false;
    paint(el, item, index);
  }
}
```

槽位复用适合没有本地状态的条目：纯文本、图标、从数据里读出的勾选。只要起点变化，可见槽位都会换绑。写在节点上的状态会串到新的索引。用这种池，换绑前要复位，或者根本不在节点上留状态。

当前快照里不存在的索引不要沿用上一帧的画面。上面的函数把超出条数的槽位藏起来，避免旧内容留在屏幕上。

### 按标识复用

宿主记住自己现在的标识。标识还在新窗口里，就继续用这个宿主；标识离开窗口，把宿主归还；新进入的标识从空闲宿主里领。

```typescript
type Host = {
  key: string | null;
  el: HTMLElement;
};

function ensurePool(pool: Host[], needed: number) {
  while (pool.length < needed) {
    pool.push({ key: null, el: createHost() });
  }
}

function takeHost(pool: Host[], key: string): Host {
  const matched = pool.find((host) => host.key === key);
  if (matched) return matched;
  const blank = pool.find((host) => host.key === null);
  if (!blank) throw new Error('池比窗口小');
  blank.key = key;
  return blank;
}

function releaseMissing(pool: Host[], nextKeys: Set<string>) {
  for (const host of pool) {
    if (host.key !== null && !nextKeys.has(host.key)) {
      resetHost(host.el);
      host.key = null;
    }
  }
}
```

`createHost` 只创建一个空容器。窗口移动一格时，按标识复用只会换绑离开的那一个宿主，留在窗口里的条目仍是原来的节点。焦点、播放中的媒体、没有写入数据的选区，才留得下来。

标识在快照里必须唯一。示意里的 `takeHost` 在标识已经绑定时会返回原来的宿主。两个索引若共用一个标识，就会先后写进同一个节点。要防御这种情况，第二个索引再次领取时应当直接拒绝。

在组件框架里，若这一帧只把窗口内的条目交给协调器，并且每条都带稳定标识，协调器就在做按标识复用。那种情况下不必再手写一套节点池。手写池用于直接操作节点，或需要自己限制实例数量的时候。两种做法用的是同一套身份规则。

### 归还时复位

宿主和一条数据解开时，清掉绑在那条数据上的东西：

- 文本，以及只对那条数据有意义的属性
- 为那条数据注册的监听
- 非受控输入的值和选区
- 焦点。焦点还在这个宿主里时，先决定它落到哪里，避免它掉到文档根上
- 媒体进度、临时的图片地址
- 写在节点上的尺寸。高度的正式记录在标识的缓存里

可以留下的是与具体条目无关的结构：宿主元素、子节点骨架、通用的样式。骨架留下来是为了少创建节点。骨架上的内容不能留。

复位发生在换绑之前。先写新数据、再指望它盖住旧字段，漏掉的字段会串。标识没变的宿主不要复位，否则列表稍一滚动，输入框里的字就被清掉。

## 标识

标识选择的是数据，不是槽位编号，也不是宿主在池里的下标。

用索引做标识，只在「这份快照的前缀不会插入、删除、重排」时成立。头部插入、排序、过滤、删掉中间某一条，都会让原来的索引指向另一条数据。结果通常是两种：协调器把节点当成全新的，焦点和输入丢失；或者节点被留下，状态贴到了新索引上。后者更难注意到。

标识需要满足三条：

- 在当前快照里唯一
- 同一条逻辑数据换了快照仍然不变
- 不掺进会变的渲染结果，比如把标题和当前高度拼在一起

没有标识时，若悄悄退回索引，上面的失效会原样出现。应当在数据进入列表之前补上稳定的业务 id，而不是渲染时现造一个。

位置是布局算出来的偏移，标识是身份。不能靠「离顶部多少像素」找回一条数据，也不能靠标识直接推出它这一帧的偏移。高度缓存用标识做键，交给滚动层时再按当前快照换成索引。

## 可变高度

### 估计值与实测值

每条高度都相同时，第 i 条的偏移是索引乘以行高，不必测量。高度随内容变化时，偏移是前面各条高度之和。这张高度表由列表层按当前快照提供，求和与滚动位置属于滚动层。

条目还没进过窗口，就没有实测。此时用估计高度，窗口才算得出来。估计值要标明来源。它参加这一帧的计算，不表示「已经量过，以后不用再量」。条目进入窗口并完成布局之后，用实测覆盖估计。

```typescript
type SizeRecord = {
  height: number;
  source: 'estimate' | 'measured';
};

function readHeight(record: SizeRecord | undefined, estimate: number): SizeRecord {
  return record ?? { height: estimate, source: 'estimate' };
}
```

测量读宿主的边框盒。写回缓存时，键是数据标识，不是宿主，也不只是索引。同一个宿主下一帧可能已经换了数据。尺寸只留在节点上，换绑之后量到的是新数据，旧数据的高度却丢了。还没进入窗口的条目，高度只活在这份缓存里。

也可以在布局完成后用 `ResizeObserver` 接收尺寸。回调里仍然按标识写入缓存。不要在回调里同步改样式再立刻读布局，那会把一帧里的测量放大成每个条目一次来回。

一帧之内先写完窗口里的内容，再集中读取高度，最后一次交出变化。读一条、改一条样式、再读下一条，布局成本会跟着条目数涨。

图片尚未解码、手风琴尚未展开，这类还会变高的条目，要把标识标回待测。下次它在窗口里，再量一次。标成实测后又永不失效，第一次的错误高度会一直参与它上方的占位。

视口变宽、字号变化、容器宽度变化，也会让已测高度失效。按标识把记录标成待测即可，不必把池拆掉。

### 缓存比宿主活得久

条目滑出窗口，宿主可以归还，高度记录留下。在它再次进入窗口之前，滚动层还要用这条高度计算占位。按索引保存、并在复用时覆盖，会把别人的高度写进已经滑出的那一格。

第一帧按估计高度准备的宿主，可能不够用。实测更矮时，同一视口装得下更多条，下一帧窗口变长。池要按新的窗口长度补宿主。窗口长度是滚动层的输出，池的容量跟上一次输出。

### 把变化量交到锚点的哪一侧

实测和缓存中的旧值不同，就产生一条变化。

```typescript
type SizeChange = {
  key: string;
  index: number;
  prev: number;
  next: number;
};
```

锚点记的是标识。比较之前，先在这一帧的快照里把标识换成索引。

- 变化的索引小于锚点索引：这条在锚点上方。上方变高之后，同样的内容离文档顶部更远。要让视口里的画面保持不动，滚动偏移要加上两次高度的差。列表层把变化交出去，由掌握滚动偏移的那一层施加
- 变化的就是锚点，并且锚在该条目的顶边：顶边不动，条目向下长，滚动偏移不变
- 变化的索引大于锚点索引：影响的是锚点以下的内容。滚动偏移不变，总占位变长

只改缓存、不交变化，上方一张图片加载完成后，正在读的那一行会被顶下去。只改滚动偏移、不改缓存，下一次按高度表求和又用到旧值，跳动会在后面的帧回来。

水平列表记录的是宽度，规则相同。网格仍然按索引取数据。一个可视行里有多列时，先约定索引按行还是按单元格，高度表和窗口必须使用同一种约定。

吸顶的那一条若在滑出窗口后还要留在视口里，它就不再使用普通池中的宿主，需要单独的节点。复用时不要把这个节点拿去画别的数据。

## 窗口上的一帧

`range` 和锚点来自滚动层，`source` 是这一帧认定的快照。示意代码假定快照里的标识唯一。

```typescript
type Range = { start: number; end: number };

function renderWindow<T>(
  source: Source<T>,
  range: Range,
  pool: Host[],
  sizes: Map<string, SizeRecord>,
  estimate: number,
): SizeChange[] {
  const changes: SizeChange[] = [];
  const needed = range.end - range.start;
  ensurePool(pool, needed);

  const nextKeys = new Set<string>();
  for (let index = range.start; index < range.end; index++) {
    nextKeys.add(source.key(index));
  }
  releaseMissing(pool, nextKeys);

  for (let index = range.start; index < range.end; index++) {
    const key = source.key(index);
    const host = takeHost(pool, key);
    paint(host.el, source.item(index), index);
    const prev = readHeight(sizes.get(key), estimate);
    const measured = host.el.offsetHeight;
    sizes.set(key, { height: measured, source: 'measured' });
    if (prev.height !== measured) {
      changes.push({ key, index, prev: prev.height, next: measured });
    }
  }

  return changes;
}
```

先按窗口长度补池，再归还离开窗口的宿主，然后为新标识领取宿主。标识还在窗口里的宿主不会复位。测量写进 `sizes`，键是标识。返回的变化交给滚动层，按锚点的哪一侧决定偏移要不要修正。

这个函数不计算窗口的起止，也不改滚动偏移。

## 用一组数字走一遍

六条数据，标识就是 a 到 f。高度里标出估计或实测：

| 索引 | 标识 | 高度 | 来源 |
|------|------|------|------|
| 0 | a | 40 | 实测 |
| 1 | b | 80 | 实测 |
| 2 | c | 40 | 估计 |
| 3 | d | 120 | 实测 |
| 4 | e | 40 | 实测 |
| 5 | f | 40 | 估计 |

滚动层第一次给出的窗口是索引 1 到 5，也就是 b、c、d、e。锚点是 d，锚在 d 的顶边。池里准备 4 个宿主。这一帧之前它们都是空的，所以四个标识各领一个，没有宿主需要复位。

c 进入窗口后量到 72，不再是估计的 40。c 的索引 2 小于锚点索引 3，列表层交出变化：标识 c，旧高度 40，新高度 72。滚动层把偏移加上 32，视口里 d 的顶边才不会被顶走。缓存里 c 改成 72，来源改成实测。b、d、e 的实测没有变化，不交非零差值。

下一帧滚动层把窗口改成索引 2 到 6，也就是 c、d、e、f。列表层不做「为什么会变成这四个」的计算，只处理宿主：

- b 不在新窗口里，它的宿主归还：清掉 b 的文本和监听，标识置空
- c、d、e 的标识还在，宿主不动，也不复位。渲染只更新能从数据推导的字段
- f 领走刚才空出来的宿主，写入 f 的内容

f 量出来仍是 40，和估计相同，不交非零变化，来源改成实测。池的长度还是 4。数据若在后面再追加一百条，只要窗口仍是 4 个索引，宿主就不增加。

如果这一帧不是窗口平移，而是在索引 0 插入一条新数据，a 到 f 的索引全部加一，标识不变。c 的高度仍然记在 c 上，不会跟着旧索引 2 走。锚点仍是 d，滚动层要用 d 去新快照里找它现在的索引，而不是继续钉着插入前的 3。

## 常见错位

**用索引当标识，同时允许头部插入或排序。** 高度、勾选和输入会整表移动，或在重排后贴错行。

**高度按索引缓存。** 窗口一滑动，滑出的位置被写成新条目的高度，上方占位跟着错。缓存的键用标识，交给滚动层时再换成当前索引。

**换绑时不复位。** 按槽位复用时尤其明显。非受控输入、图片地址、表示展开的类名留在槽位上，数据已经是新的，界面还是旧的。

**标识没变，渲染却覆盖了非受控字段。** 节点留住了，值仍然每帧被数据写回。草稿若还没进数据，就不要在这种渲染里赋值。

**把估计值当成最终值。** 条目从未测量，或图片解码后没有把标识标回待测。重叠、空隙、滚动条长度不对，都从这里来。

**上方变高，却不交变化量。** 缓存已是新高度，滚动偏移还是按旧高度留下的数，视口被顶走。

**同一帧混用两份快照。** 滚动层按筛选前的索引要窗口，列表层已经换成筛选后的数组。应当整份替换快照，用锚点标识在新快照里重新取窗口。锚点标识在新视图里不存在时，改钉到仍存在的邻近条目，或回到起点，并把窗口收进新的条数之内。

**池按数据条数创建。** 文档里仍然有完整的一份节点。池的长度等于这一帧的窗口长度，窗口变长再补。

**把渲染当成曝光。** 窗口里多准备的条目也会走渲染函数。统计「看见」要用视口，而不是池里有没有这个标识。

## 总结

虚拟列表是滚动窗口上面的那一层。数据源给出可以按索引读取的快照，并为每条数据提供稳定标识。渲染函数把条目写进宿主，并承认这个宿主可能画过别的数据。复用池按窗口长度保留宿主：槽位复用实现直接，标识复用能留下仍在窗口内的节点状态。高度缓存以标识为键，比宿主活得更久。估计值用来撑起还没量过的条目。量到差异之后，把变化量和它相对锚点的位置交回滚动层。

窗口怎么划定、总占位怎么铺、滚动时哪一帧回收，留在滚动层。列表层要保证的是：窗口里每个索引画的都是该索引上的那条数据，离开窗口的节点不带走上一条的状态，变过的高度下一帧仍然认得出是谁。
